VmOps 使用帮助

VmOps 是一款专为企业虚拟化维护人员设计的批量虚拟机部署与自动化配置工具。本工具通过 CSV 文件配置虚拟机参数，利用 PowerShell + VMware PowerCLI 与 vCenter Server 或 ESXi 主机 交互，实现虚拟机的批量创建、自动配置 IP 地址等网络参数，大幅减少重复性手工操作，降低工作负载，提升运维效率。

核心功能

  • 批量部署虚拟机：通过 CSV 模板文件批量定义虚拟机配置（CPU、内存、存储、网络、网关、掩码等），一键完成多台虚拟机的创建与部署
  • 资源查询与管理：实时查询虚拟机、主机、存储、网络等资源列表，支持搜索过滤、导出 CSV、双击查看详细信息
  • VM 日常运维：分组下拉右键菜单，涵盖远程连接、电源管理、编辑配置（vCPU/内存智能升降、端口组、GuestOS 网络与密码）、磁盘管理、迁移克隆、快照管理、删除等全栈操作
  • 批量操作：多选 VM 后批量执行电源操作、快照操作、删除虚拟机、批量迁移（主机 vMotion / 资源池 / Storage vMotion）
  • VMRC 远程控制台：在虚拟机详情页一键打开 VMware Remote Console 远程控制台
  • 在线编辑列表：内置表格编辑器，导入 / 编辑 / 保存 CSV 部署模板文件，无需外部工具
  • OVF Tool 集成：支持导出/导入/转换 OVF/OVA/VMX 格式
  • 连接凭据记忆：自动保存 vCenter / ESXi 连接配置与密码，支持连接别名，减少重复输入

关于本工具

本工具最初为企业内部虚拟化维护团队日常运维而开发，经过长期生产环境的实际使用与持续优化，已具备稳定可靠的批量部署能力。

本工具已在实际生产环境中长期稳定运行，适用于需要频繁批量部署虚拟机及日常运维的企业场景。

一、环境准备

VmOps 依赖 VMware PowerCLI 模块与 VMware vCenter Server 或 ESXi 主机进行交互。使用前请确保已安装 PowerCLI。

1. 在线安装

1以管理员身份打开 PowerShell

按 Win + X，选择"Windows PowerShell (管理员)"。

2设置执行策略
Set-ExecutionPolicy RemoteSigned
3设置信任 PSGallery 安装源并安装
Set-PSRepository -Name PSGallery -InstallationPolicy Trusted
Install-Module -Name VMware.PowerCLI

2. 脱机安装（推荐）

无法联网的环境请使用以下两种方式之一，优先选择一键脚本自动安装。

方式一：一键脚本自动安装（推荐）

1以管理员身份打开 PowerShell

按 Win + X，选择"Windows PowerShell (管理员)"。

2复制并执行以下脚本

脚本会自动从下载服务器获取 PowerCLI ZIP，解压、解除阻止、完成全部配置：

$zipUrl = 'https://developer.broadcom.com/tools/vmware-powercli/latest/'
$zipPath = "$env:TEMP\powercli.zip"

$isAdmin = ([Security.Principal.WindowsPrincipal] [Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)
if ($isAdmin) {
    $destDir = "$env:ProgramFiles\WindowsPowerShell\Modules"
    Write-Host "[管理员] 安装到全局模块目录: $destDir"
} else {
    $destDir = "$env:USERPROFILE\Documents\WindowsPowerShell\Modules"
    Write-Host "[非管理员] 安装到当前用户模块目录: $destDir" -ForegroundColor Yellow
}

try { Set-ExecutionPolicy RemoteSigned -Scope CurrentUser -Force -ErrorAction Stop } catch { }

Write-Host "[1/4] 下载 PowerCLI ZIP..."
curl.exe -L -o "$zipPath" "$zipUrl"
if ($LASTEXITCODE -ne 0) { Write-Error "下载失败，curl 返回码 $LASTEXITCODE"; exit 1 }
if (-not (Test-Path $zipPath)) { Write-Error "下载失败，请检查网络或手动下载"; exit 1 }

Write-Host "[2/4] 解压到 $destDir ..."
New-Item -ItemType Directory -Path $destDir -Force | Out-Null
Expand-Archive -Path $zipPath -DestinationPath $destDir -Force

Write-Host "[3/4] 解除文件阻止..."
Get-ChildItem $destDir\VMware* -Recurse -File | Unblock-File

Write-Host "[4/4] 配置 PowerCLI 并验证..."
Set-PowerCLIConfiguration -InvalidCertificateAction Ignore -Confirm:$false
Get-Module -ListAvailable VMware.PowerCLI | Select Name, Version

Write-Host "✓ 脱机安装完成，可关闭此窗口后打开 VmOps 使用。"
说明：curl.exe 是 Windows 10/11 / Server 2019+ 自带的命令行工具（不是 PowerShell 的 Invoke-WebRequest），可直接使用。
下载地址来自 Broadcom 官方仓库，如遇网络不可达，请使用方式二手动下载。

方式二：手动安装（备用）

  1. 如果需要脱机安装 PowerCLI，请从 PowerCLI 下载页 获取 ZIP 文件，或从内部文件服务器下载 VMware-PowerCLI.zip，传输到目标计算机。
  2. 使用 $env:PSModulePath 查看 PowerShell 模块路径
  3. 将 ZIP 文件内容解压到其中一个列出的文件夹中（推荐 $env:ProgramFiles\WindowsPowerShell\Modules）
  4. 进入模块目录，执行 Get-ChildItem * -Recurse | Unblock-File 取消文件阻止
  5. 使用 Get-Module -Name VMware.PowerCLI -ListAvailable 验证安装
  6. 忽略证书验证：Set-PowerCLIConfiguration -InvalidCertificateAction Ignore

3. PowerCLI 配置

1查看已安装的模块
Get-Module -ListAvailable VMware*
2忽略证书验证
Set-PowerCLIConfiguration -InvalidCertificateAction Ignore
3加载 PSSnapin（旧版本需要）
Add-PSSnapin vmware.vimautomation.core

三、操作流程

1. 连接资源

本工具支持两种连接目标，程序会根据用户名自动识别连接模式并采用相应的连接参数：

模式自动识别规则：
  • ESXi 直连模式：当用户名为 root 时，自动使用 -Force 参数连接单个 ESXi 主机，无需填写用户域
  • vCenter 模式：当用户名为 administrator 或其他域用户时，使用完整域用户格式（域\用户名）连接 vCenter Server
1填写连接信息
字段说明vCenter 示例ESXi 示例
连接别名可选，为当前连接起一个易记的名字（如"生产集群VC"、"测试主机ESXi01"），方便快速切换生产VCESXi-Node01
连接地址vCenter Server 或 ESXi 主机的 IP / 域名（下拉框自动记忆多个地址）192.168.200.88192.168.1.200
用户域vCenter 连接需填写（预设 vsphere.local / local.net 等）；ESXi 直连留空即可vsphere.local（留空）
用户名选择或输入用户名（预设 root / administrator），填 root 即为 ESXi 模式administratorroot
2开始连接

点击"开始连接"按钮，首次连接会弹出密码输入框。连接成功后凭据自动保存（含别名、地址、域、用户名、密码），下次可通过别名下拉快速选择历史连接，无需重新输入。

3刷新缓存（可选）

连接成功后点击功能菜单跳转到各资源查询 Tab，程序会自动采集虚拟机、主机、存储、网络资源信息到本地缓存，后续切换 Tab 页时加载更快。

4断开连接

点击"断开连接"按钮断开当前会话（vCenter 或 ESXi）。

5重置记忆

在输入框中选择要清除的地址后，点击"重置记忆"按钮清除该服务器的已保存密码和连接配置。

2. 执行部署

2编辑部署列表

点击"编辑列表"按钮打开内置表格编辑器，为每台虚拟机配置 IP 地址、子网掩码和网关等参数；也可以直接用 Excel / 文本编辑器编辑 CSV 文件。

esxcli storage filesystem unmount -l <LUN名称> esxcli storage filesystem unmount -u <UUID> esxcli storage filesystem unmount -p <挂载点路径>

esxcli storage core device set --state=off -d <NAA_ID>

esxcli storage core device list -d <NAA_ID>

2. ESXi 单台主机 NFS 4.1 存储不可访问故障处理

2025-04-18 10:30

1. 故障现象

  • 集群内仅单台 ESXi 主机（192.168.5.192）的 NFS 4.1 数据存储显示「不可访问」，容量显示为 0B；其余同集群主机挂载正常。
  • 基础网络验证正常：vmkping 到 NFS 服务端零丢包，nc 测试 TCP 2049 端口连通成功。
  • NFS 服务端（192.168.5.197）服务、权限、目录均正常，无配置变更。
  • vCenter 界面显示存储名称带 (1) 后缀（如 nas-data (1)），属于清单缓存重复条目。

2. 根因定位

  1. 网络中断恢复后，ESXi 本地 NFS 4.1 客户端挂载会话僵死：内核保留卷记录，但实际 TCP 会话已失效，表现为 Accessible: false、Mounted: false，容量读取失败。
  2. 命令混用误区：esxcli storage nfs 是 NFS v3 专用命令，无法识别和操作 NFS 4.1 卷，会误判为「无挂载」。
  3. 卷名不匹配：vCenter 清单缓存生成带 (1) 的重复名称，用该名称执行删除会报 Failed to remove unknown volume。

3. 解决步骤（业务无影响，无需重启主机）

步骤 1：确认真实卷名与状态（NFS 4.1 专用命令）

# 查看本机所有NFS 4.1卷状态，获取真实卷名 esxcli storage nfs41 list

输出示例关键信息：

  • Volume Name: nas-data（真实名称，无 (1) 后缀）
  • Accessible: false
  • Mounted: false

步骤 2：强制移除僵死卷

使用真实卷名执行删除，清理内核僵死挂载记录：

esxcli storage nfs41 remove -v "nas-data"

若提示资源占用，可先执行懒卸载再删除：
umount -l /vmfs/volumes/nas-data

步骤 3：验证清理结果

# 确认卷已移除 esxcli storage nfs41 list # 确认挂载点已消失 df -h | grep nfs

步骤 4：命令行重新挂载 NFS 4.1

绕过 vCenter 界面缓存，直接在 ESXi 本地执行挂载：

esxcli storage nfs41 add -H 192.168.5.197 -s /nas/pacs -v nas-data

参数说明：

  • -H：NFS 服务端 IP 地址
  • -s：服务端共享目录路径
  • -v：本地数据存储名称

步骤 5：验证挂载恢复

esxcli storage nfs41 list

正常状态：Accessible: true、Mounted: true，df -h 可读取到正确容量；vCenter 界面会自动同步状态，「不可访问」提示消失。

4. 关键注意事项

  1. 命令区分版本：NFS v3 使用 esxcli storage nfs 子命令，NFS 4.1 使用 esxcli storage nfs41 子命令，二者不通用。
  2. 卷名以本地为准：删除 / 挂载操作的卷名，必须以 esxcli storage nfs41 list 输出为准，禁止直接使用 vCenter 界面显示的带 (1) 后缀名称。
  3. 业务安全：上述操作仅清理客户端挂载缓存、重建会话，不会影响 NFS 服务端数据，也不会中断其他主机的正常挂载。

#!/bin/sh # 自动创建ESXi快照 for i in `vim-cmd vmsvc/getallvms | grep -v nosnap | awk '{print $1}' | grep -e "[0-9]"` do vname=$(vim-cmd vmsvc/get.summary $i | grep name | awk '{print $3}' | cut -d\" -f2) vim-cmd vmsvc/snapshot.create $i $(date "+%F") sleep 30s if [ $? -eq 0 ]; then echo "$(date "+%F%T"): $vname snapshot create success.." >> ./schedule_snap.log else echo "$(date "+%F%T"): $vname snapshot create FAILED.." >> ./schedule_snap.log fi done

删除过期快照脚本（snapshot_del.sh）

#!/bin/sh DAY=5 # 保留天数 for i in `vim-cmd vmsvc/getallvms | awk '{print $1}' | grep -e "[0-9]"` do SNAPSHOT_COUNT=`vim-cmd vmsvc/snapshot.get $i | egrep -- '--|-CHILD|^|-ROOT' | wc -l` if [ $SNAPSHOT_COUNT -gt $DAY ]; then DELETE_COUNT=$((SNAPSHOT_COUNT-DAY)) OLD_SNAPSHOT_ID=`vim-cmd vmsvc/snapshot.get $i | grep Id | head -$DELETE_COUNT | awk -F: '{print $2}'` for n in $OLD_SNAPSHOT_ID do vim-cmd vmsvc/snapshot.remove $i $n > /dev/null sleep 30s done fi done

添加定时任务

在 ESXi 主机的 crond 任务配置文件 /var/spool/cron/crontabs/root 中添加如下内容。推荐方式：编辑 /etc/rc.local.d/local.sh，让主机在启动时自动写入 crond 任务：

/bin/echo "01 1 * * * sh /vmfs/volumes/5a0eeb56-e924f565-353e-e04f430764dc/crontabs/snapshot_creat.sh" >> /var/spool/cron/crontabs/root /bin/echo "30 1 * * * sh /vmfs/volumes/5a0eeb56-e924f565-353e-e04f430764dc/crontabs/snapshot_del.sh" >> /var/spool/cron/crontabs/root kill $(cat /var/run/crond.pid) crond

  • 凌晨 01:30 — 执行 snapshot_del.sh，超过保留天数（默认 5 天）的旧快照将被自动删除

八、常见问题与错误处理

A. 常见问题

1. 保存的密码存储在哪里？

密码通过 Windows DPAPI（Data Protection API）加密后保存在 %APPDATA%\VmOps\credentials.json 文件中，绑定当前登录用户，其他账户无法解密。首次输入密码后自动保存，后续连接无需重新输入。可通过主页"重置记忆"按钮清除。

2. 部署后 IP 地址未生效怎么办？

检查虚拟机模板的 Guest OS 类型是否受当前 ESXi 版本支持，Linux 需安装 cloud-init，Windows 需确保模板系统的管理员密码正确。

3. 如何打开虚拟机的远程控制台？

在虚拟机列表中双击某台虚拟机打开详情页，点击顶部"打开 VMRC"按钮。需提前安装 VMware Remote Console 客户端。

4. 会话失效后如何处理？

程序内置心跳保活机制，会话断开后会自动尝试静默重连。若自动重连失败，会弹窗提示手动重连。也可通过主页"断开连接"后重新连接。

B. 常见错误处理

1. PowerCLI 命令无法识别

Set-PowerCLIConfiguration : 无法将"Set-PowerCLIConfiguration"项识别为 cmdlet、函数、脚本文件或可运行程序的名称。

解决方法：按"环境准备"中的步骤安装 PowerCLI。

2. 连接 vCenter / ESXi 失败

Connect-VIServer : 无法连接到服务器

解决方法：确认服务器地址正确且 443 端口网络可达、用户名密码正确、证书状态正常。
vCenter：确认用户域填写正确（如 vsphere.local），用户名应为域用户格式（如 administrator）。
ESXi 直连：用户域留空，用户名使用 root，程序会自动添加 -Force 参数连接。

3. 部署虚拟机失败 - 找不到模板/网络/存储

New-VM : 找不到模板 / 网络不存在 / 存储不可用

解决方法：确认 CSV 中的资源名称与当前连接的服务器（vCenter / ESXi）中完全一致（区分大小写）。可使用"刷新缓存"后通过资源列表查看正确的名称。

4. 资源不足

解决方法：选择其他有足够资源的主机或存储。

5. CSV 文件编码问题

解决方法：用 Excel 或 VS Code 重新保存为 UTF-8 BOM 编码。

6. VMRC 控制台无法启动

未检测到 VMware Remote Console

解决方法：下载并安装 VMware Remote Console 客户端。确保客户端出站 443 和 902 端口放行。
